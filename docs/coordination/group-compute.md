## Gaussian 如何分工

- 推荐粒度：一名组员负责一个或多个完整反应，各反应独立输出，其他人无需等待。
- 每个反应保留 TS 优化/频率、正反向 IRC、两个端点优化/频率及最终连接检查。
  不能只交回优化后的 TS 或单个能量就算完成验证。
- 同一反应内部有依赖：IRC 使用已完成 TS 的频率/checkpoint，端点优化使用对应
  IRC 的结果。当前代码按 forward/minimum、reverse/minimum 顺序执行；它没有
  自动跨主机分发分支的功能。跨人分配优先整条反应，避免一天一次的依赖交接。
- 本轮九个策略评价单元去重成三个相同坐标候选任务。按唯一任务 ID 分配，
  相同候选只算一次，再关联回全部策略，不能把复用当成额外独立样本。
- 固定方法/基组、原子顺序、坐标、电荷/多重度、积分/SCF、优化/IRC 参数和
  验收阈值；记录 Gaussian 版本、平台、核数、内存、起止时间及所有恢复尝试。
  跨平台 checkpoint 的可用性未验证，任务包应包含从显式几何开始的输入，
  并让有依赖的后续步骤在接收方的同一环境内完成。
- 现有 OMEN 任务每个配置 4 核/4 GB。这是当前执行资源设置；分发包需明确
  每个任务的资源分配和机器可同时运行的数量，避免组员各自无记录地改输入。

## 交给组员前必须具备的内容

| 项目 | 任务包内容 |
| --- | --- |
| 输入 | 固定的数据、原子映射、模型版本或权重获取方式、数据与模型许可信息 |
| 身份 | 协议版本、代码提交、软件/硬件版本、任务 ID、种子 |
| 环境 | 项目独立环境与依赖锁；协调脚本依赖 fcntl，Windows 需 WSL；当前 Gaussian 调用桥是 OMEN Windows 路径，其他平台必须准备相应启动入口 |
| 命令 | 一条启动命令、输出目录、断点恢复方式和重复执行规则 |
| 资源 | 由本地试跑得到的显存、内存、CPU/GPU使用量和大致时长 |
| 验收 | 已完成、化学失败、基础设施错误分开；不只回传成功案例 |
| 回传 | 全部 .gjf/.log、结果 JSON、TS/端点几何、运行清单、失败和恢复记录；同一任务只认一份终态，checkpoint 作为续算证据单独保存 |
| 时间 | 适应一天回传周期，当前关键流水线不依赖临时互动或马上拿结果 |

后续任务一旦有具体规模、试跑成本和明确输入，由协调模型先把任务包写好，
再告诉用户有多少项、每人需要什么设备、预计多久；不直接联系组员。
