# 组员计算分工准备

用户在 2026-11-22 确认可安排组员一起做大量、明确、对时效要求不高的计算，
但结果可能一天后才回传。目前没有向组员发送消息或派发任务。

## 当前轮次

v0.5.0 已冻结 OMEN 软件、设备、实现和模型身份，当前矩阵继续在 OMEN 完成。
Mac 与 ROG 负责可并行的报告、测试和终态产物核验。当前没有需要组员立即接手的计算包。

## 合适的下一轮任务

当 v0.5.0 完整结果可用后，可独立规划多随机种子训练或更多新反应的端点搜索。
每个任务必须能独立结束、失败后独立回收，并有项目全局不重复的任务 ID。
此前开发或保留数据已用于方法诊断，不能再把相关结果当成未见测试。
具体反应、种子、训练规模与接受准则尚未固定，不把这些想法当作已分配任务。

## 交给组员前必须具备的内容

| 项目 | 任务包内容 |
| --- | --- |
| 输入 | 固定的数据、原子映射、模型版本或权重获取方式、数据与模型许可信息 |
| 身份 | 协议版本、代码提交、软件/硬件版本、任务 ID、种子 |
| 环境 | 项目独立环境与依赖锁；当前Linux脚本依赖fcntl，Windows需WSL |
| 命令 | 一条启动命令、输出目录、断点恢复方式和重复执行规则 |
| 资源 | 由本地试跑得到的显存、内存、CPU/GPU使用量和大致时长 |
| 验收 | 已完成、化学失败、基础设施错误分开；不只回传成功案例 |
| 回传 | 结果JSON、原始日志、几何/轨迹、任务身份；同一任务只认一份终态 |
| 时间 | 适应一天回传周期，当前关键流水线不依赖临时互动或马上拿结果 |

后续任务一旦有具体规模、试跑成本和明确输入，由协调模型先把任务包写好，
再告诉用户有多少项、每人需要什么设备、预计多久；不直接联系组员。
