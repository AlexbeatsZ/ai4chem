# 有意专门化：共享标签与等总更新预算

2026-11-23 用户提出主动训练只在部分区域特别好的专家，并保留通用回退。
本轮检验条件性能优势，不把人为损坏非目标区域当收益，也不预先保证专家
组合胜过通用模型。外部异构专家的 v0.7 比较和本轮训练分别保留。

## 标签、分区及封存

`configs/v0.8.0.json` 在新标签准备和训练前固定方案。训练为原 256 条反应
加 256 条新的官方 train 反应；新增 ID 排除旧项目反应、128 条 meta-development、
两组 prospective holdout 和全部 validation。仍用固定 13 shard/revision。
每反应八个完整历史的 path8 构型，保留老 anchor；新增 anchor 用固定种子
抽样。端点、TS 邻域和几何多样性取样规则与 v0.7 一致，共 4096 个唯一标签。

只用 512 条训练反应的端点特征，训练中位数填补和标准化，再做两个平衡的
几何聚类。中心初始化复用 SciPy kmeans2；固定中心时按两中心距离差的中位
边界精确均分，迭代更新中心至分区不变。每区 256 条/2048 帧。边界几何
完全相同时拒绝依靠 reaction ID 强拆。特征白名单不含参考能、力、TS 或误差。
这只是几何专门化，不提前把两个聚类命名为已经证明的化学机制或困难区域。
后续可在新的训练侧误差诊断后研究弱点专门化，本轮不据 meta 误差反向分区。

原 60 条 validation 按固定端点门控分到各区域，每区至少八条，否则准备
失败而不启动训练。专家按其区域 validation loss 选择 checkpoint。通用模型
对照的两个成员也分别使用同样的区域 validation，排除 checkpoint 选择
方式本身带来的优势。单一通用模型使用全部 60 条。

`configs/v0.8.0_partitions.json` 在训练前保存具体 ID、门控、回放 ID 和时间。
后续 128 条 meta 只开发路由；64+64 条 prospective holdout 继续封存。
实际冻结为 155 个化学式、432 条重排/58 条裂解/22 条成键；区域 validation
分别 29/31 条。区域 0/1 中成键反应为 3/19 条，不能据此当作均衡的机制分类。

## 等总更新预算的四个系统

全部从同一 MH-1/omol 基础权重全参数微调，float64、batch 4、lr 1e-4、
energy/force 权重 10/1、E0 estimated、no_scaling。先保持原优化器隔离
专门化效果；优化器改进在单独对照研究。patience 100，固定 epoch 上限，
报告全部运行及实际日志 epoch/最佳 checkpoint/墙钟，不只挑最好的种子。

| 系统 | 每模型标签 | 模型数 | epoch | 系统总更新数 |
| --- | ---: | ---: | ---: | ---: |
| 单一通用 | 4096 | 1 | 40 | 40960 |
| 两个通用种子对照 | 4096 | 2 | 20 | 40960 |
| 两个分区专家 | 2048 | 2 | 40 | 40960 |
| 两个带目标数据回放专家 | 2560 | 2 | 32 | 40960 |

配对的通用/专家/回放成员分别用相同 seed 20261116、20261117；单模型用前者。
所有系统共享同一批 4096 个唯一 DFT 标签。回放从对方区域取 64 条完整反应
的 512 个已有帧，加到本区 2048 帧，不增加标签。这是目标 DFT 数据回放，
不是官方 foundation multihead replay，也不证明保留了全部基础训练域行为。
等更新不等于精确 FLOPs 或墙钟，原子数和设备并发的影响需如实记录。

## 部署规则和比较

每条反应固定一个专家走完整路径。第一种真实规则就是冻结的端点分区；
距离超过该区训练距离 99% 分位时回退到已经存在的旧微调 MH-1。所有系统
都共享这个旧模型，不能将新训通用模型作为专家系统不计成本的额外回退。
几何 OOD 阈值是启发式，不是精度概率。

全部新模型在同一 60 条 validation 和 128 条 meta 上评价；后者比较固定
端点门控、分组 OOF 学习路由和不可部署 oracle。报告目标区/非目标区、能垒、
全路径力、TS 力、反应能、尾部及成本。需要区分更强底层模型、多个种子和
专门化各自的贡献。独立 holdout 必须等最终模型、门控和预算冻结后才打开。

## 运行

OMEN 的完整原数据准备：`scripts/launch_model_study.ps1 -Stage specialization-prepare`。
准备与当前 CUDA 队列独立，产物 `data/v0.8.0`，完整读回检查标签和预算。
Mac 接收数据、冻结配置及已有单头 foundation 后，使用现有 mac-mace Pixi
环境运行 `python -u run_specialization.py`。每模型四 CPU 线程，最多三个
并行；先等待三家族端点搜索先导终态，避免 CPU 过度竞争。
可用系统自带的进程级 `caffeinate -i` 保持这项任务期间唤醒，不改全局电源配置。

逐模型状态/官方日志在 `results/v0.8.0/training/<name>`；总状态在
`results/v0.8.0/state.json`。同一模型有证据但无完成 manifest 时先检查中断，
不会覆盖；完成项按配置与产物复用。队列完成后仍不自动打开 holdout。
