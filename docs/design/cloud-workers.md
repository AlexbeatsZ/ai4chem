## 2026-11-23 晚：先独立准备模型训练

用户明确 Linux g16 可能次日提供，要求今天推进可在云上训练的部署，并判断
本地是否根本不能训练。ML 与 Gaussian 的技术依赖分开：先做隔离 ML 安装、
CUDA 推理/短训练和可搬运的开发数据计时包；原生 Linux Gaussian 验收和后续
云节点/五人分发仍分别保留，不从 ML 通过推导 Gaussian 或真实云通过。

`validate_cloud_omen.sh ID install|ml` 默认 ml；旧 Windows 桥接被移除，
不会再生成笼统的本地部署通过。`launch_cloud_validation.ps1 -Mode install`
只安装，不启动 GPU 训练。pip 对网络增加5次连接/续传重试，保持证书校验、
固定包版本和索引，不调整代理/驱动/现有研究环境。

`prepare_cloud_training.py --source-config ... --output ...` 从已有开发训练配置
导出原始 train/validation/foundation，移除旧输出目录和自动恢复设置，生成
固定2epoch、30分钟上限的 CUDA 计时清单；保留 float64/batch/loss/seed。
它是基础设施复算，不加入科学比较、不替换活跃研究任务、不打开 holdout。
云上先用水分子验能量/力/训练重载，再用真实4096帧计时，记录初始化和实际
epoch耗时；未经同任务测量不承诺4090或其他租赁卡的加速倍数。

已完成的 OMEN v0.7 实测表明当前模型和 batch4 可以训练：256/2048/4096
帧40epoch分别约24分钟/1小时51分/3小时30分。现有8GiB显存容纳当前设置，
不意味着更大模型、更多原子或更大batch均可容纳；增加总标签数主要增加
更新数量和运行时，不能直接把数据集大小当作单批显存占用。
Mac已有原生CPU真实训练日志；ROG仅分析环境通过，尚无MACE训练验收。
当前科研目标是微调，未验证从头预训练大型通用势的设备/时间可行性。

## 无人值守的五人成对训练重复

用户补充：长训练适合拆给组员，交付任务尽量不需要负责人看守。
`prepare_group_training.py` 准备五份互相独立的配对重复，每份两个顺序训练：
原random4096与path4096，同一MH1/omol、256反应×16帧、validation60、
float64/batch4/lr1e-4/energy10/force1/40实际epoch。patience100确保跑满；
种子固定20261124–20261128，避开v0.9及活跃队列的20261116–18。
这回答既有取样差异能否跨种子重现，不是新的holdout或五次挑最好模型。
已有v0.7单种子用于开发选型，保留其身份，五个新配对全部报告差值/离散度/成本。
总预算10次训练、估计409600更新，按OMEN观测约7h/份，实际云耗时未保证。
仅准备，原LinuxGaussian/用户云验收/分发门槛保持；不启动十次新计算。

每份ZIP包含部署脚本与固定依赖锁、两套训练帧、validation、foundation及成员任务清单。
组员在解压目录运行一次 `bash member-01/start.sh`，无需编辑路径/配置，
后台顺序执行安装、设备检查、水分子能量/力/短训练重载、两个固定任务，
任务单项12h上限。无需在线选参/等负责人反馈；每项只尝试一次，独立下一项
仍会继续，成功与失败都入档，最终自动生成output.tar.gz供回传。
负责人统一检查固定版本/epoch/返回模型和化学指标，不让组员凭最低loss挑模型。
单独主机断电/销毁与进程被强杀不属于nohup可恢复范围，不能宣称断电续训。
